## 对 chat.deepseek.com 的深度逆向 + 复刻客户端（dswui）

**取证对象**：`main.a34f79a498.js` / `default-vendors.3473f64207.js` / `main.4591aecc90.css`（commit `6c40ca01`），
与工作区已有的两份观察文档互补，新增协议层与设计令牌层的证据。

**新增实证结论**：

- 构建链：**Rspack**（`data-rspack` 注入、chunk 名 `@deepseek/chat:`）+ **Lightning CSS**（`--lightningcss-*`）
- 运行时：React 19（另有一份 react-dom 18.3.1 副本）、Zustand v5（`zustand/traditional` 文案）+ Immer、SWR、React Router
- 输入框是原生 `textarea`；`slate` 是 `translate` 的子串假阳性（`data-slate*` 全 0 命中）
- 传输层无 `EventSource` / 无 `getReader`，是自研 XHR 适配层里手写 SSE 解析；与微信小程序同构（`platform==="miniprogram"`）
- 桌面端 Tauri（`__TAURI__`）；i18n 为自研内联字典
- SSE 事件机：`ready / delta / close / finish / title / toast / update_session / hint / update_parent_message / update_file`，
  心跳头 `x-ds-sse-heartbeat-timeout-secs`，ready 60s 超时，`resume_stream` 续传
- completion 请求体：`chat_session_id / parent_message_id / model_type / prompt / ref_file_ids / thinking_enabled / search_enabled / source / action / preempt`
- PoW 反爬 `create_pow_challenge`，挑战计算在 Worker
- 消息模型：`fragments[]`（THINK/RESPONSE/SEARCH/TIP/TOOL_OPEN/TOOL_SEARCH）+ `childIds`/`currentChildIndex` 多叉分支
- 能力位由服务端 `client/settings` 的 `model_configs` 下发（`think_feature`/`vision`/`tts_feature`/`edit_quota`…）
- 设计令牌：品牌色 `#3964fe`，neutral-bluish 色阶，侧栏 `261px`，列表 `840/712px`，正文 `16/28px`，缓动 `cubic-bezier(.4,0,.2,1)`

**产出**：

- `docs/deepseek-protocol-and-tokens.md`（新，协议与令牌）
- `src/` 完整实现：React 18 + Vite + TS，zustand/persist，markdown-it + hljs + KaTeX，自写 SSE 客户端
- `npm run build` → 单文件 `dist/index.html`（约 2.1MB，含内联 KaTeX 字体）
- `tools/mock-server.cjs`：本地 OpenAI 兼容 SSE mock，无 Key 也能跑通全链路

**踩过的坑（复用价值高）**：

1. 单文件内联时，用 `str.replace(re, js)` 会被 JS 里的 `$&`/`$'` 当成替换模式 → 必须用函数形式 `replace(re, () => js)`。
2. 内联脚本还要把 `</script` 转义成 `<\/script`，否则 JS 里的字符串会把 `<script>` 提前闭合（表现为整页显示源代码）。
3. 无头 Edge 截图 + CDP（Node 内置 `WebSocket`）比装 agent-browser 轻，可直接抓 console 错误。
4. mock 的 SSE 必须 `res.flushHeaders()`，否则部分客户端读不到分块。
5. 流式渲染要节流（60ms 合并 store 写入 + Markdown 渲染节流），否则每个 token 都重解析整篇。
